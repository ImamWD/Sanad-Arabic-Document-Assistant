# Ingestion failure fixtures

Five files that ingestion must reject, each with its own error code. `seed/render.py` generates all of them (`make render-seed`), and the output is byte-identical on every run. None of them holds anything harmful: they are built from the synthetic seed corpus and generated bytes.

| File | What it is | Expected `error_code` (SYSTEM_DESIGN §5.2) |
|---|---|---|
| `truncated.pdf` | The first 30% of `annual-report-2016.pdf`. The cut falls before the page tree and the cross-reference table. | `FILE_CORRUPT` |
| `encrypted.pdf` | `annual-report-2016.pdf` encrypted with AES-128. The user password `FAKE-open-1234` is needed to open it (owner password `FAKE-owner-1234`). | `PDF_ENCRYPTED` |
| `scanned-no-text.pdf` | Pages 1–2 of `annual-report-2016.pdf`, rasterised to greyscale at 110 dpi and wrapped in a PDF with `img2pdf`. Like a scan, it has no text layer. | `NO_TEXT_LAYER` |
| `empty.docx` | A valid Word document with no text at all. | `EMPTY_DOCUMENT` |
| `not-a-pdf.pdf` | Starts like a Windows executable (`MZ` DOS header pointing at a `PE` signature), followed by 4 KiB of generated filler. It is not a runnable program, only the first bytes of a header. | `UNSUPPORTED_TYPE` if the upload sniffs content, otherwise `FILE_CORRUPT` |

The codes are what the design table implies. B3 owns the final mapping and its tests.
